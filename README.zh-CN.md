RecompOne 是一款将 PlayStation 1 可执行文件静态重编译为 C# 代码的工具。它还提供了一个运行时层，将 PS1 硬件环境转换为现代 PC 可原生运行的形式。

本项目的灵感来自 [N64Recomp](https://github.com/N64Recomp/N64Recomp) 和 [XenonRecomp](https://github.com/hedge-dev/XenonRecomp)，它们分别是面向 N64 和 Xbox 360 的类似工具。

我们也有一个 Discord 服务器：https://discord.gg/65g8ZEPnbR

## 工作原理

静态重编译与模拟类似，都会重现硬件的内部状态；区别在于，重编译器不会在运行时逐条取出、解码并执行指令，而是提前将所有 MIPS 操作转换为代码。

生成的代码在 `CpuContext` 和内存接口上运行。`CpuContext` 封装了 CPU 应有的状态，而运行时会模拟 PS1 硬件的行为，并将其转换为现代硬件能够理解的形式。

例如，一条加法指令：
```asm
addiu t0, t0, 0x10
```
会变为：
```csharp
c.T0 = c.T0 + 0x10u;
```

而一条内存读取指令：
```asm
lw t0, 0x10(sp)
```
会变为：
```csharp
c.T0 = mem.Read32(c.SP + 0x10u);
```

与模拟器类似，运行时会模拟游戏所期望的行为，例如 BIOS 函数、MMIO、GPU 绘图命令和 CD-ROM 等。它还重新实现了部分 PsyQ 库，因为其中严重依赖中断的库无法在重编译器下正常工作。

## 覆盖层

由于 PS1 的 RAM 极其有限，PS1 游戏会使用覆盖层，按需将代码和数据加载到同一内存区域或从中卸载。

每个覆盖层都在配置文件中定义。重编译期间，系统会为每个覆盖层生成一个单独的类，并生成一张覆盖层分发表。
分发器会跟踪运行时当前加载的覆盖层，并按需更新函数映射。之所以需要这样做，是因为不同的覆盖层可能会在不同时刻占用相同的 VRAM 地址范围；运行时会按需加载和卸载它们，确保每个虚拟地址始终解析到正确的重编译函数。

## 补丁

你可以提供补丁来完整替换某个函数。

补丁在重编译配置中注册：
```json
{ "address": "800553C4", "name": "MyPatch.MyClass.MyMethod" }
```
补丁类本身位于重编译后的项目中。你需要创建一个文件并实现被补丁替换的函数，然后将其重定向。

这可用于为游戏提供“基础模组”，例如修复重编译器无法处理的函数（如自修改代码），或加入简单的体验优化功能。

## 贡献

欢迎任何形式的贡献。本项目最初主要是一个兴趣项目，我没有想到它真的能够运行起来；不过，要达到 N64Recomp 等类似工具的成熟度，仍有很长的路要走。我不会说这个工具已经可以用于制作真正的重编译版本，但它确实能够启动游戏。

目前我是该项目唯一的维护者，空闲时间有限，编程能力也并不完美，因此非常欢迎任何帮助，无论是错误报告、功能建议，还是实际代码贡献。

## 对 AI 的立场

本项目并非通过“vibe coding”编写，代码编写过程中没有使用 AI！

本项目不支持通过“vibe coding”制作的移植版本。AI 可以是一种有用的研究工具，但它不能取代理解并正确实现所构建内容所需的人类判断。

你可以自行选择做法，但我不会为以这种方式制作的移植版本提供帮助。
