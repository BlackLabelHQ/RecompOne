RecompOne は、PlayStation 1 の実行ファイルを C# コードへ静的再コンパイルするツールです。また、PS1 のハードウェア環境を現代の PC でネイティブ実行できる形へ変換するランタイム層も提供します。

このプロジェクトは、N64 と Xbox 360 向けの類似ツールである [N64Recomp](https://github.com/N64Recomp/N64Recomp) と [XenonRecomp](https://github.com/hedge-dev/XenonRecomp) に着想を得ています。

Discord サーバーもあります：https://discord.gg/65g8ZEPnbR

## 仕組み

静的再コンパイルは、ハードウェアの内部状態を再現する点ではエミュレーションに似ています。異なるのは、実行時に各命令をフェッチ、デコード、実行する代わりに、リコンパイラがすべての MIPS 操作を事前にコードへ変換する点です。

生成されたコードは、`CpuContext` とメモリインターフェース上で動作します。`CpuContext` は CPU が持つべき状態をカプセル化し、ランタイムは PS1 ハードウェアの動作をシミュレートして、現代のハードウェアが理解できる形へ変換します。

たとえば、加算命令：
```asm
addiu t0, t0, 0x10
```
は次のようになります：
```csharp
c.T0 = c.T0 + 0x10u;
```

また、メモリ読み取り命令：
```asm
lw t0, 0x10(sp)
```
は次のようになります：
```csharp
c.T0 = mem.Read32(c.SP + 0x10u);
```

エミュレータと同様に、ランタイムは BIOS 関数、MMIO、GPU 描画コマンド、CD-ROM など、ゲームが想定する動作をシミュレートします。また、割り込みへ強く依存する PsyQ ライブラリはリコンパイラ上で正常に動作しないため、その一部を再実装しています。

## オーバーレイ

PS1 の RAM は極めて限られているため、PS1 ゲームはオーバーレイを使用し、必要に応じて同じメモリ領域へコードやデータをロードしたり、そこからアンロードしたりします。

各オーバーレイは設定ファイルで定義されます。再コンパイル時には、オーバーレイごとに個別のクラスとオーバーレイディスパッチテーブルが生成されます。
ディスパッチャーは、実行時に現在ロードされているオーバーレイを追跡し、必要に応じて関数マッピングを更新します。異なるオーバーレイが別の時点で同じ VRAM アドレス範囲を使用する可能性があるため、この処理が必要です。ランタイムがオーバーレイを必要に応じてロードおよびアンロードすることで、各仮想アドレスは常に正しい再コンパイル済み関数へ解決されます。

## パッチ

関数を完全に置き換えるパッチを指定できます。

パッチは再コンパイル設定に登録します：
```json
{ "address": "800553C4", "name": "MyPatch.MyClass.MyMethod" }
```
パッチクラス自体は再コンパイル済みプロジェクトに置かれます。ファイルを作成してパッチ対象の関数を実装し、その関数へリダイレクトする必要があります。

これは、リコンパイラが処理できない関数（自己書き換えコードなど）の修正や、簡単な QoL 機能の追加といった、ゲーム向けの「ベース Mod」を提供するために使用できます。

## コントリビューション

あらゆるコントリビューションを歓迎します。このプロジェクトは主に趣味として始めたもので、実際に動作するものができるとは思っていませんでした。しかし、N64Recomp などの類似ツールと同程度に成熟するまでには、まだ長い道のりがあります。このツールが実用的な再コンパイル版を作れる段階にあるとは言えませんが、ゲームを起動することはできます。

現在、このプロジェクトのメンテナーは私一人で、自由に使える時間も限られており、プログラミング能力も完璧ではありません。そのため、バグ報告、機能提案、実際のコードなど、どのような形の支援も大歓迎です。

## AI に対する姿勢

このプロジェクトは「vibe coding」で作られたものではありません。コードの作成に AI は使用していません！

このプロジェクトは、「vibe coding」で作られた移植版をサポートしません。AI は有用な調査ツールになり得ますが、何を構築しているのかを理解し、正しく実装するために必要な人間の判断に代わるものではありません。
